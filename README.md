# nankan-keiba

南関東競馬（大井・川崎・船橋・浦和）の予想用データを集めるためのツールです。
第一段階として、[netkeiba 地方競馬](https://nar.netkeiba.com/) から **過去のレース結果**（着順・オッズ・タイム・払戻・コーナー通過順・ラップ）をサーバーに負担をかけないよう取得し、SQLite / CSV に保存します。

## 利用規約・マナーについて

netkeiba の[利用規約](https://www.netkeiba.com/info/kiyaku.html)（2026-10 時点で確認）では主に以下が定められています。本ツールはこれらを守る前提で作っています。

| 規約 | 内容 | 本ツールでの対応 |
| --- | --- | --- |
| 第14条 | 私的利用の範囲を超える複製・販売・出版の禁止。不特定多数が見られる状態に置く行為も禁止 | **個人の予想研究専用**。取得データ・キャッシュ (`data/`) は `.gitignore` 済み。公開リポジトリやWebへアップロードしないでください |
| 第15条 | 営利目的での利用・その準備の禁止 | 予想の販売・有料配信などには使わないでください |
| 第16条(12) | サービス設備の運営に支障を与える行為の禁止 | 下記の負荷対策を実装 |

robots.txt は 2026-10 時点で存在しません（HTTP 404）が、実行のたびに確認し、今後設置された場合は `Disallow` と `Crawl-delay` に従います。

### 負荷対策（`nankan_keiba/client.py`）

- **直列実行のみ**（並列リクエストなし）。リクエスト間隔は既定 3 秒 + 0〜1 秒のランダム。2 秒未満は設定不可
- **取得済みページは gzip でローカルキャッシュ**し、同じ URL へは二度とアクセスしない。DB に保存済みのレースは結果ページ自体を取りに行かない（中断後は続きから再開）
- 429 / 5xx・通信エラーは `Retry-After` または指数バックオフ（最大 10 分）で最大 3 回まで再試行。**連続 5 回失敗で中止**
- **403 を受けたら即中止**（アクセス制限のサインとして扱う）
- 1 回の実行あたりのリクエスト上限（既定 1,500 件）
- アクセス先は `https://nar.netkeiba.com` のみに制限。ログインや有料コンテンツには一切アクセスしない
- 結果が確定していない当日以降のレースは取得しない

## セットアップ

Python 3.10 以上。

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

## 使い方

```bash
# 前日までの過去 1 年分（南関東 4 場すべて）を収集
python -m nankan_keiba collect

# 期間・競馬場を指定（42=浦和 43=船橋 44=大井 45=川崎）
python -m nankan_keiba collect --start 2026-04-01 --end 2026-09-30 --places 44 45

# 保存済みの出走馬の血統（父・父の父・母・母の父、父の系統）を収集
python -m nankan_keiba pedigree

# CSV に書き出し（Excel で開けるよう UTF-8 BOM 付き）
python -m nankan_keiba export --out data/csv
```

過去 1 年分は約 250 開催日・約 3,000 レースで、リクエスト数は約 3,300 件、所要時間は 3〜4 時間程度です。
既定の上限 1,500 件で一旦止まるので、**数回に分けて（時間をおいて）再実行**してください。保存済みのレースはスキップされます。

主なオプション:

| オプション | 既定値 | 説明 |
| --- | --- | --- |
| `--interval` | 3.0 | リクエスト間隔（秒、2.0 以上） |
| `--max-requests` | 1500 | 1 回の実行のリクエスト上限（0 で無制限） |
| `--db` | `data/nankan.sqlite` | 保存先 SQLite |
| `--cache-dir` | `data/cache` | HTML キャッシュ |
| `--refetch` | off | 保存済みのレースも取り直す（キャッシュも無視） |

## ブラウザで予想する（Web 画面）

コマンドを打たずに、ブラウザで開催日とレースを選んで予想できます。自分の PC だけで動き、外部には公開しません。

```bash
pip install -e ".[web]"   # 初回のみ
python -m nankan_keiba web
```

ブラウザで http://localhost:8501 が開きます（開かなければこのアドレスを開いてください。終了は Ctrl+C）。

Windows では、リポジトリ直下の `start_web_windows.bat` をダブルクリックしても起動できます（Python 3.12 のインストールが必要です）。初回は必要なライブラリを `.venv` に入れるため数分かかります。終了するときは黒いウィンドウを閉じます。

1. 「開催日」を選ぶと、その日の南関東の開催とレースが表示されます（既定は日本時間の今日）。
2. 「全レース（朝の予想）」か「レースを選ぶ（発走直前の予想）」を選びます。レースを選ぶと、その日の前のレースの結果から馬場傾向を計算して使います。
3. モデル（オッズなし / オッズあり）を選び、「予想する」を押します。1〜2 分でレースごとの予想表（印・勝率・3 着内率・オッズ・人気）が出ます。結果が DB に保存済みのレースは着順も表示し、CSV でダウンロードできます。
4. サイドバーの「前日までの結果と血統を取り込む」で DB を最新にし、「モデルを学習し直す」でモデルを作り直せます（月 1 回程度で十分です）。

netkeiba へのアクセスは `predict` と同じく低負荷（3〜4 秒に 1 件）で、画面を複数開いても 1 つずつ実行します。
`--db` `--model-dir` `--odds-model-dir` `--cache-dir` `--port` `--no-browser` で場所やポートを変えられます。

### 回収率の答え合わせ

「回収率の答え合わせ」タブで期間とモデルを選んで「答え合わせする」を押すと、DB に保存済みのレースをモデルで予想し直し、保存済みの払戻と照らし合わせて 1 点 100 円で買った場合の券種別の回収率を表示します（netkeiba にはアクセスしません）。コマンドでは次のとおりです。

```bash
python -m nankan_keiba simulate --from 2026-10-21 [--to 2026-10-31] [--model-dir data/model_odds] [--out sim.csv]
```

| 券種 | 買い方（◎○▲△ は予想 1〜4 位） |
|---|---|
| 単勝・複勝 | ◎ |
| ワイド・馬連 | ◎ から ○▲△ への流し（3 点） |
| 3 連複 | ◎・○ と ◎・▲ の 2 頭軸から残り全頭（重なる買い目は 1 点） |
| 3 連単 | 1 着 ◎・2 着 ○ か ▲・3 着 残り全頭 |

- 取消・除外の馬は除いて予想し、同じ日の前のレースの結果は使います（発走直前の予想と同じ条件）。オッズありモデルは確定オッズを使うので、実際に買う時点より有利です。
- 発売のなかった券種はそのレースでは買わなかったものとします。
- モデルの学習期間に含まれる日は実際より成績が良く出るため、画面に注意を表示します。

## 取得の流れ

1. 月間カレンダー `top/calendar.html?year=&month=` から南関東 4 場の開催日（`kaisai_id`）を抽出
2. 開催日ごとのレース一覧 `top/race_list_sub.html?kaisai_date=` から `race_id` を抽出
3. 各レースの結果ページ `race/result.html?race_id=` を解析して保存
4. （`pedigree`）血統表は競走馬データベース `db.netkeiba.com/horse/ped/<horse_id>/` から 1 頭 1 リクエストで取得します。
   最後に出走した日が新しい馬から順に取り、取得済みの馬は二度と取りに行きません（約 1 万頭で 10 時間程度。1,500 件ごとに止まるので再実行してください）。
   読み取れなかった馬は空の血統として保存します。robots.txt の確認・間隔・停止条件は結果ページと同じです。

`race_id` は `YYYY` + 競馬場コード(2) + `MMDD` + レース番号(2)（例: `202544090111` = 2025年 9月1日 大井 11R）。

## データ構造（SQLite / CSV）

**races**（1 レース 1 行）: `race_id, race_date, place_code, place_name, race_number, race_name, grade, post_time, surface, distance, direction, weather, track_condition, kai, nichi, race_class, num_horses, prize_money, corner_passing(JSON), lap_times(JSON)`

**results**（1 頭 1 行）: `race_id, finish_position, finish_status(取消/除外/中止 等を含む生値), bracket_number, horse_number, horse_id, horse_name, sex, age, weight_carried, jockey_id, jockey_name, finish_time, finish_time_sec, margin, popularity, win_odds, last_3f, trainer_affiliation, trainer_id, trainer_name, horse_weight, horse_weight_diff`

**payouts**（1 払戻 1 行）: `race_id, bet_type, combination, payout_yen, popularity`
（`combination` は `-` 区切り。馬単・枠単・3連単は着順どおりの並び）

**pedigrees**（1 頭 1 行）: `horse_id, sire_id, sire_name, sire_line(例: Mr. Prospector系), sire_sire_id, sire_sire_name, dam_id, dam_name, damsire_id, damsire_name`

`horse_id` / `jockey_id` / `trainer_id` は netkeiba の ID なので、今後の血統・馬柱情報の取得でキーとして使えます。

## 着順予想（LightGBM）

収集済みのレース結果で学習し、結果の出ていないレースの出馬表から勝率・3 着内確率・予想順位を出します。

```bash
# 学習（既定では直近 20% の開催日を検証用にして評価を表示し、data/model/ に保存）
python -m nankan_keiba train
python -m nankan_keiba train --valid-from 2026-08-01   # 検証期間の開始日を指定
python -m nankan_keiba train --use-odds                # 単勝オッズ・人気も特徴量に使う
python -m nankan_keiba train --objective lambdarank    # レース内の順位を直接学習（既定は binary）

# 予想（出馬表を取得。CSV は data/predictions/ に保存）
python -m nankan_keiba predict --date 2026-10-12 --places 45
python -m nankan_keiba predict --race-id 202645101201 202645101202
```

- **教師データ**: 確定済みレースの各馬。取消・除外は学習から外し、中止は着外として扱います。
- **学習方式**（`--objective`）:
  - `binary`（既定）: 1 着（`is_win`）と 3 着内（`is_top3`）を別々の二値分類で学習します。
  - `lambdarank`: レースを 1 グループとして、レース内の順位を直接学習します（関連度は 1 着 3・2 着 2・3 着 1・着外 0）。スコアはレース内 softmax で勝率に変換し、3 着内確率は Plackett-Luce モデルで計算します。softmax の温度と 2・3 着の割引係数は、学習期間の直近 20% を除いて学習し直したモデルで、除いた期間に合わせます。
- **特徴量**（`nankan_keiba/features.py`）: すべて「そのレースより前」の結果だけから作ります。同日の結果は、同じ競馬場でそのレースより前に終わったレースの馬場傾向（下記）だけに使い、それ以外の集計は前日までです。
  - 馬: 出走数・勝率・3 着内率、前走からの日数、距離変更、前走/直近 3・5 走の相対着順・タイム差（勝ち馬との差）・上がり 3F 順位・人気、同競馬場での勝率・3 着内率、同距離での成績、基準タイム差・人気応答率・先行度（下記）
  - 基準タイム差: 同じ競馬場・コース・距離・馬場状態で前日までに走った全馬の平均タイムとの差（1000m あたりの秒）。サンプルが 30 頭未満なら馬場状態を問わない平均を使います。前走・直近 3/5 走平均・直近 5 走ベストと、そのレース内順位を使います
  - 人気応答率: log2(人気 ÷ 着順)。人気より上の着順なら正の値になります（中止は最下位扱い）。馬は前走と直近 5 走平均、騎手は前日までの全騎乗の平均を使います
  - 先行度: 最初に記録されたコーナーでの位置 ÷ 頭数（小さいほど前。同じ位置の馬は同じ値）。前走・直近 3/5 走平均と、そのレース内順位を使います
  - 騎手・調教師: その時点までの勝率・3 着内率、騎手と馬のコンビ回数、騎手の競馬場別の騎乗数・勝率・3 着内率
  - コース特徴: ゴールまでの直線と 1 周距離（浦和 220m/1200m、船橋 308m/1400m、川崎 300m/1200m、大井外回り 386m/1600m・内回り 1500/1600m は 286m/1400m・左回り 1650m は 300m/1600m。地方競馬情報サイト・日刊競馬のコース解説による）
  - 先行有利度（`course_front_adv`）: 同じ競馬場・距離で前日までに、最初のコーナーで前 1/3 にいた馬の 3 着内率 − 後ろ 1/3 にいた馬の 3 着内率（各 100 頭未満なら競馬場全体の値）。脚質との相性（`style_fit`）は (0.5 − 馬の直近 5 走の先行度) × 先行有利度、`race_front_runners` はそのレースで直近 5 走の先行度が 0.25 以下の馬の数（先行争いの激しさ）
  - 所属: 調教師の所属を「地元（レースの競馬場）・南関東の他場・JRA（美浦/栗東）・他地区・不明」に分類。JRA 騎手かどうか（騎手 ID が 01 始まり）、そのレースの JRA 所属馬の頭数（交流競走の目安）。JRA 所属馬は南関東での過去成績がないことが多く、その場合は過去成績の特徴量が欠損になります
  - 血統: 父の系統（カテゴリ）と、父・母の父・母（兄弟姉妹）の産駒の前日までの南関東での成績（出走数・勝率・3 着内率）。父は距離区分別・競馬場別・重/不良馬場での 3 着内率と、産駒の基準タイム差の平均も使います。過去成績のない馬（デビュー戦・転入初戦）の手がかりにするためです
  - 当日の馬場傾向: 同じ日・同じ競馬場でそのレースより前に終わったレースの、先行有利度（前 1/3 と後ろ 1/3 の 3 着内率の差。各 4 頭以上のとき）とそのコースのふだんの値との差、内枠有利度（馬番が内 1/3 と外 1/3 の 3 着内率の差）、基準タイム差の平均（時計の速さ）、勝ち馬の先行度の平均、前に終わったレース数。脚質・馬番との相性（(0.5 − 先行度) × 先行有利度、(0.5 − 馬番/頭数) × 内枠有利度）も使います
  - 当日条件: 競馬場、距離、馬場状態、頭数、枠番・馬番、斤量、馬体重・増減、性別・年齢、クラス
- **予想**: レース内で勝率の合計が 1 になるよう正規化し、勝率の高い順に予想順位を付けます。
- **評価**: 時系列で学習期間と検証期間を分け、LogLoss・AUC、本命の勝率・3 着内率、本命単勝の回収率を、1 番人気を買い続けた場合と比較して表示します。
- **注意**:
  - 出馬表は内容が変わるためキャッシュしません（1 レース 1 リクエスト。`--date` 指定時はレース一覧の 1 リクエストが加わります）。
  - 馬場状態・馬体重は発表前だと欠損になります。発走直前に実行するほど入力が揃います。
  - 当日の馬場傾向は、同じ競馬場でそれより前のレースの結果ページ（確定済みのもの）を取得して計算します。結果が出ていないレースに当たるとそこで止めます。発走直前に `--race-id` で 1 レースずつ予想すると、前のレースの結果を最大限使えます。
  - 出走馬に血統が未取得の馬がいれば、その馬の血統表も取得します（1 頭 1 リクエスト）。
  - `--use-odds` モデルの予想時のオッズは netkeiba の「予想オッズ」で、確定オッズとは異なります。
  - 回収率などの評価値は検証期間のデータ量に左右されます。将来の的中や収益を保証するものではありません。
